# 第四阶段编码前模型审计

## 语义对照与结论

| 原Simulator真实约定 | CP-SAT必须表示的约束 |
| --- | --- |
| 单机器人、单夹爪、完整transfer/unload独占机器人 | 每次传输区间包含空载定位、取片、载片移动、放片；机器人NoOverlap |
| 空载定位从前一任务放片目的地出发 | 机器人任务序列用Circuit表示；相邻任务决定定位耗时，首任务用initial_position |
| 接受传输时目标已预留，不能仅等到PlaceComplete才算占腔 | 腔室保留/占用区间从传输接受时刻开始 |
| 未加工完成不能接受转移，即使取片之前还要定位 | 下一传输开始不早于当前实际加工结束 |
| 放片完成立即启动加工，无任意延迟加工权利 | 工序开始等于对应入腔传输结束，结束=开始+选定腔室耗时 |
| 加工完成仍占腔，PickComplete才释放 | 占腔末端为下一次传输的取片完成时刻，包含定位及取片 |
| 同片连续两工序可在同一腔室取放，验证器有own_source例外 | 同腔连续工序的逻辑占用区间在下一传输接受处交接，合并后的物理占用连续；不误报同片内部冲突 |
| 工序有recipe及eligible chambers，不能自由互换 | 每工序恰好选择一个兼容腔，optional intervals关联选腔变量 |
| 机器人位置LOAD/OUT或任意腔室，位置方向影响运输 | 使用完整有向travel矩阵，self travel=0，与RobotConfig.travel一致 |
| 初始晶圆在LOAD，腔室空、机器人空闲不持片 | 精确固定批次初始状态，支持配置的任意合法机器人初始位置 |
| 同刻全部事件处理后再接受新动作 | 半开资源区间允许端点相接；严格正取/放时间避免零长度资源区间歧义；回放再检验同刻语义 |
| 既有run_until(T)通过事件队列加入观测边界 | 受控回放可等待到排程时刻，处理所有更早事件，不直接写时钟；没有提前独立空载移动 |

结论：可以准确表示**静态确定性、原始空设备初始化、完整传输动作粒度**下的问题。不能把本阶段模型称为全部动态仿真功能的完整模型。仅对该范围内模型与回放都通过、求解器返回OPTIMAL且时间域未排除最优解的实例声明最优。

## 明确不一致/未支持项

- 故障暂停加工、移动/放片中故障及等待恢复：第一版拒绝任何downtimes；不悄悄移除故障窗口。
- 中途occupied/paused/carrying/busy初始化：当前EquipmentConfig本身不编码任意暖启动；第一版只接受原Simulator构造出的空设备批次初始状态。独立验证器拒绝中途仿真器，后续滚动规划再扩展。
- 未宣布到达：统一对照全部0秒释放。模型可显式接受已宣布的确定性释放表，但这是离线已知输入，不提供给在线启发式隐藏事件；含延迟释放的最优性测试单列，不混作在线公平对照。
- 容量>1、有限中间缓冲、独立提前定位、任意工艺替换路线：原宏动作模型不支持这些能力，CP-SAT不增加这些自由度。现有route是必须的工序序列，只优化每工序合法候选腔室。
- 时间量化：使用能精确表示配置十进制秒的整数tick，不向上/向下取整。无法精确表示或scale过大时明确拒绝。取/放秒必须为正；零加工/零移动可以表示，零取/放作为未支持配置报告。
- 指标：共同窗口的WPH、腔室加工利用率、机器人利用率沿用日志积分；Makespan独立。额外完成窗口WPH明确标注，不替代共同窗口指标。

## 实施门禁与证明边界

先实现单片手算、同腔互斥、重复同腔、方向性定位；然后将CP计划逐动作交给原validate_action/submit/事件推进，核对机器人取放及加工记录。模型内部检查不能代替这个回放。

默认时间域上界使用把所有晶圆完全串行处理的可行保守界（最大兼容工艺时间及最大定位/移动时间），不删除可能更优解；用户主动设置较窄horizon或额外目标上下界时，INFEASIBLE仅说明被限制模型不可行，OPTIMAL仅指该限制问题。使用真实已验证规则解作hint及上界，不伪造求解器界限。保存OPTIMAL/FEASIBLE/INFEASIBLE/UNKNOWN/MODEL_INVALID，UNKNOWN无方案不回放，不用启发式结果冒充CP解。

第三阶段五场景和五规则原代码/历史产物保持不变，第四阶段重新运行六算法并独立保存。扩大晶圆数、腔数、工序数/重入及机器人竞争，记录建模时间、求解时间、下界和验证结果。单线程固定seed用于尽量可重现搜索；墙钟限时可能改变FEASIBLE方案和证明进度，重复seed不能作为独立随机环境样本。

OR-Tools接口参考官方[整数模型及状态定义](https://developers.google.com/optimization/cp/cp_solver)、[Python约束接口](https://or-tools.github.io/docs/pdoc/ortools/sat/python/cp_model)。这些只支持工具接口说明，设备约束以上述本仓库代码为准。
