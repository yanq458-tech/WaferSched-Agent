# 一次启动的离线维修边界搜索

适用于现有归档中有有限上界、有可重放下界、故障位于时间原点的均匀搬运终端快照。输入由 `results/local/offline-resume-008` 的清单和验收账本发现。六个未决例进入队列，已经有定论的实例不占专项预算。沿用已验收的历史上界，并在每次启动时用 Simulator 核验当前下界见证。

在仓库根目录运行：

```powershell
.\scripts\RunRecoveryCampaign.ps1 -Seconds 1800
```

参数是整批新分配的离线搜索秒数。默认 180 秒。脚本从 5 秒时间片起步，读取最近至多八次精确求解的反馈。若至少四次且全部 UNKNOWN，下一轮根据实测求解耗时自动将时间片提升到 10–40 秒。在剩余总预算内自动进入下一轮，也可用 `-Slice 15` 等参数调整。时长用于控制搜索，初始化、模型构造、最后一次验证和写盘可能带来额外墙钟开销。命令使用项目原有 Python 环境及已编译的本地构造器。默认输出 `results/local/boundary-campaign-009`。相同目录自动续算，指定新的 `-Output` 从同一历史归档重做。运行期间用 SQLite 文件锁防止两个写入者竞争；每完成一个动作就原子替换检查点。意外中断只需重做最后一个未保存动作。

## 算法与判定

- 每个快照保存全局可行下界 L、对应的原语时间表和一组互斥分支。初始分支是最后一次进腔搬运的所有可能序号。每个分支保存自己的上界 Uᵦ。全局上界为 max(L, maxᵦ Uᵦ)。Uᵦ≤L 的分支可以移出队列。
- 对一个分支，直接最大化整数维修刻度 r，范围为 L+1 到 Uᵦ。若在序号 u 将晶圆放入故障腔，约束为 r≤此次放片开始时刻。工序、机器人、腔室与驻留限制复用现有精确分组模型。找出方案后提取路线和顺序、重新计算原语时刻，并在原故障历史上重放；成功后提高 L。
- 若搜索区间被 CP-SAT 证明不可行，该分支对超过 L 的解已无贡献。若求解器返回可行解和有效目标上界，则同时利用两侧证据。UNKNOWN 自身引起的上下界变化为零。任何降低分支上界的 CP 模型都以压缩 protobuf 和 SHA-256 保存。
- 确定性控制器在快照间轮转。在同一快照内，每四次分配一次构造搜索，交替挑战 L+1 和区间中部，用变化的种子寻找更好的搬运顺序。其余时间先处理上界最高的分支。未决分支反复超时，自动按最后进腔的晶圆身份、候选腔路线依次细分。已固定最后晶圆并达到条件时，改试一次年龄流松弛，只有整数复算后的严格正对偶下界才排除相应刻度和更晚修复。限时失败只影响下一步的工具选择。
- 所有分支上界都不超过已重放的 L，才宣告精确边界；所有快照闭合或本批预算用完则退出。预算耗尽时输出每例区间和最新见证。该流程优化维修延迟，见证的完工时间仅用于描述方案。本入口没有二级最短完工时间证明。

## 怎么检查结果

`summary.json` 给出每例的起止区间（秒）、状态和见证路径。`state.json` 保存当前分支、已执行动作、种子和区间变化（整数刻度）；`steps/` 保存新方案及重放、降低上界时的 CP 模型和正对偶证书。`checked/` 保存本次启动时的下界重放。归档证据、快照、构造器、主控制模块及 OR-Tools 版本与检查点绑定；项目底层工艺语义改变时应使用新的输出目录并重新验收。该专项搜索预算独立于原 18 例的 1 秒与 30 秒对照，不能用专项输出替换计时成绩。

小规模检查涵盖直接最大化与搬运顺序/腔室分配穷举的一致性、返回方案重放、超时保界、分支覆盖和历史排除的单调性。
