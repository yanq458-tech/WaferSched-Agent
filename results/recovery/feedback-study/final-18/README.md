# 同一组 18 个快照的最终维修边界

快照来自冻结的 [value-agent-002 输入清单](../value-agent-002/manifest.json)，为单臂、暂时单腔故障设备模型生成的数据。每片还剩一道加工和出片，时间刻度为 0.125 秒。下表列出从故障时刻算起、仍能让全部有效晶圆完成剩余工序的最大修复延迟。“立即无解”表示可行延迟集合为空。[逐例输入哈希、秒数、整数刻度及证据路径](cases.json)

| 晶圆数 | 竞争 | 种子 1 | 种子 2 | 种子 3 |
|---|---|---:|---:|---:|
| 16 | 中 | 86.5 | 88.625 | 86.875 |
| 16 | 高 | 立即无解 | 33 | 立即无解 |
| 20 | 中 | 104.125 | 106.375 | 106.5 |
| 20 | 高 | 立即无解 | 立即无解 | 38 |
| 24 | 中 | 122.5 | 123.375 | 114.75 |
| 24 | 高 | 59.75 | 3.875 | 17 |

14 个有限时限均有完整可重放方案和匹配上界。4 例在立即修复时即不可行。该结论适用于列出的输入和工艺约束。

## 两个 24 片实例的上下界

| 快照 | 合法排程支持的修复延迟 | 已排除的相邻时刻 | 全部腔室分配 | 核验的分组记录 |
|---|---:|---:|---:|---:|
| [24-h-2](proofs/24-h-2/verification.json) | [3.875 秒](proofs/24-h-2/schedule.json) | 4 秒 | 2,048 | [177](proofs/24-h-2/proof-ledger.json) |
| [24-h-3](proofs/24-h-3/verification.json) | [17 秒](proofs/24-h-3/schedule.json) | 17.125 秒 | 4,096 | [2,349](proofs/24-h-3/proof-ledger.json) |

下界从冻结输入重放取、移、放和整批出片。上界枚举工艺允许的腔室分配，按单腔必要工作量过滤，再核对剩余分配的末片组合。每个组合都须由已完成的不可行搜索或足以排除目标刻度的上界覆盖。时钟约束搜索允许使用外包络，只有外包络已排除目标时刻才能据此排除原分支。提早修复仍可等待，因此排除相邻较晚刻度也排除了所有更晚刻度。

## 离线复核

先按仓库 README 安装研究环境。在仓库根目录，使用已安装项目依赖的 Python 和 Windows .NET Framework 4.x 编译器运行：

```powershell
.\results\recovery\feedback-study\final-18\proofs\check.ps1 -Python python
```

默认校验 18 个输入哈希、14 份排程和结果索引，检查已有短程证书，为 4 个分支证明实例重新执行穷举，并为两个 24 片实例重建路线、核验源文件哈希、分组覆盖及归档求解记录。要从源码再次运行这两个实例的每条分组搜索，可添加 `-RerunCuts -Cache D:\wafer-proof-cache`；这会重建搜索索引，可能耗时较长。使用普通 Python 模式运行，校验程序使用断言。跨平台单独核对输入、证书和见证可设置 `PYTHONPATH=src` 并执行 `python results/recovery/feedback-study/final-18/verify_results.py`。
