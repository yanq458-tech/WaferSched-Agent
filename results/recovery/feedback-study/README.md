# 临界故障快照：反馈策略开发与第二批留出实验

目标和可行动作沿用原项目。结果分为带历史见证的开发续算、从原始快照冷起解的计时盲测、计时外的证据复核。在制晶圆、动作完成端点、合法候选腔和独立重放规则沿用原模拟器。模型与必要条件的推导见[技术说明](../../../docs/recovery-feedback.md)。

## 上一轮留下的 10 例

开发组中仍无见证的 20-h-f1、20-h-f2、24-h-f1 又各自接受了单独的 60 秒零维修精确查询，全部返回 UNKNOWN。另一项 30 秒诊断允许放宽源取片期限，并最小化最大迟到量，三例分别找到迟到 47、66、83 刻度的方案，三个已证下界均为零。它们既不能充当原问题的合法方案，也无法证明原问题无解。三例继续保留区间。[计时外模型与回执](rechecks/)

### 20-m-f2 的原差异

旧首轮直接调用在 21.222 秒内搜索 267,301 个分支并证明边界。旧 Agent 搜索 25.454 秒，完成 106,140 个分支，仅有可行下界。后者在优化返回后另外花 3.674 秒重放。旧反序运行的两种入口分别只走 65,057 和 66,211 个分支，都未证明。两种入口重建的模型序列化 SHA-256 都以 b14f7704 开头，种子和工作线程数相同。把搜索预算改为同样的 0.5 个 CP-SAT 确定性工作单位，两者都走 38,984 个分支、8,102 次冲突，得到同样的 [629,858] 刻度。历史证据支持相同模型在墙钟截止前走到不同搜索进度。主机调度、负载与吞吐差异的个别贡献未测出。[历史回执与同工作量复算](diagnosis-20-m-f2.json)

随后将同工作量复算延长到完成维修边界证明。两种入口都恰好在 267,301 个分支、90,097 次冲突、12.4401741 个确定性工作单位处证明 858 刻度；实际墙钟分别为 43.31 秒和 39.13 秒。这个受控复算单独归档，不计入 30 秒成绩。[完整确定性复算记录](diagnosis-20-m-f2-work18.json)

## 新快照盲测

冻结 18 个新种子，每种规模 16、20、24 片，交叉中/高腔室竞争，每个组合 3 例。全部属于临界期限生成组。每个输入均从新快照开始，不提供上一批成绩、调度、区间或分组。求解和审计分开，原来 85% 内部预算、单线程、绑定核心和整次返回超时计 UNKNOWN 的规则继续使用。1 秒全部反序；30 秒仅对四组首轮分类有差异的 6 个实例反序。主要统计按每个快照的首轮取一次。

| 入口 | 1 秒证明 | 30 秒证明 |
|---|---:|---:|
| legacy　上一轮固定工具组合 | 0/18 | 4/18 |
| fixed　新增工具固定顺序 | 5/18 | 10/18 |
| plain　反馈决策，普通函数执行 | 2/18 | 10/18 |
| agent　同一反馈决策，LangGraph 执行 | 2/18 | 10/18 |

相对旧组合，Agent 在 1 秒新增 new-16-h-f1、new-24-h-f1；30 秒除这两例外还新增 new-20-m-f1、new-20-m-f3、new-24-m-f1、new-24-m-f3。两档均无边界证明丢失。相对新固定组合，Agent 在 1 秒丢失 new-16-m-f1、new-16-m-f2、new-16-m-f3 三个有限证明，反序也如此；30 秒双方逐例分类相同。相对同策略普通函数，Agent 两档逐例证明分类相同。共有证明的实例上，30 秒 Agent 相对新固定组合、同策略普通函数的逐例中位用时差分别是 +0.227 秒、+0.008 秒。30 秒相对新固定组合在 new-20-h-f1、new-20-h-f2、new-24-h-f2 返回的未知区间更弱。全部结果含时间退步见[逐例人读表](holdout/instances.md)、[逐次配对](holdout/paired.csv)、[成对增退汇总](holdout/paired-effects.json)。

### 反馈确实改变执行路径

在 new-20-m-f2 的 30 秒首轮，先导查询提供了验证过的见证，Agent 随即求容量上界并尝试在 835 刻度达到它，失败后探测区间内部，最终保留 [91.625,104.375] 秒。在 new-16-h-f2 的同档运行中，先导查询没有见证，第一步转为零维修可行性，随后才探测 243 和 122 刻度。在 new-16-m-f2 的 1 秒首轮，Agent 拿到零维修见证后又找到上界处方案，整次返回已到 1.363 秒，按协议不计准时证明。另两例的逐步记录保留在同一目录。反馈机制可执行，先求零维修在短预算下存在实际代价。[有见证的轨迹](holdout/b30/new-20-m-f2/0-agent.json) · [无见证的轨迹](holdout/b30/new-16-h-f2/0-agent.json) · [短预算退步](holdout/b1/new-16-m-f2/0-agent.json)

所有入口共 240 次计时求解；130 条记录附有方案，按快照、维修时刻、完工以及动作内容去重后，41 份不同方案经旧 Simulator 后缀与整机重放。30 秒 Agent 的 10 个准时结论由 8 个有限边界和 2 个即刻维修仍不可恢复组成。另 8 例保留 UNKNOWN。[盲测输入与代码冻结](holdout/freeze.json) · [运行协议](holdout/protocol.json) · [所有 UNKNOWN 回执](holdout/unknown.csv) · [独立审计](holdout/audit.json)

### 计时外的手算复核

对只能进入同一末道腔的晶圆集合，逐一假定 j 是最后从源腔取出的晶圆。此前集合内其余晶圆都必须完成进腔、加工、再出腔并放到 OUT，否则单臂取了 j 也无法腾空该腔。从每片开始取到下一笔源取片，至少耗去 2P+2L+3d+t 个刻度（t 为其加工时间）。若从最早可能开始时刻累加这一必要时长，对每一个 j 都超过 j 的最迟取片开始时刻，就连立即维修也不可恢复。冻结后的独立复核确认了两个按时的不可恢复结论；还发现计时结果为 UNKNOWN 的 new-20-h-f3 有 11 片必经 H1。遍历这 11 个可能的最后晶圆，最有利情况也迟 5 刻度，即 0.625 秒。该证明单列，不回填 10/18，也未用于修改受测策略。[逐项算术证书](exclusive-audit.json)

自动回归共 346 项通过，1 项跳过，1 项 PPO 训练测试按既有协议排除。新增小规模回归用原完整末道整数模型校验容量上界，并在精确边界和再晚一个刻度核查加强后的判定。

## 复现

在研究工作树根目录激活项目原 Python 环境。重新生成盲测要选空的新目录。归档核心编号为 2、4、6、8。单例命令输出完整反馈、见证和截止计分。

~~~powershell
$env:PYTHONPATH=(Resolve-Path src).Path
python -m wafer_sched.recovery.feedback.study solve --budget 30 --incident results/recovery/feedback-study/holdout/inputs/new-20-m-f2.json --out results/local/feedback-demo.json
$trial="results/local/feedback-holdout-rerun"
python -m wafer_sched.recovery.feedback.study generate --root $trial
python -m wafer_sched.recovery.feedback.study benchmark --root $trial --budget 1
python -m wafer_sched.recovery.feedback.study benchmark --root $trial --budget 30
python -m wafer_sched.recovery.holdout_review --root $trial
python -m pytest tests/wafer_sched/test_feedback.py -q
~~~
